# Plan: Meeting File Upload and Display

**PRD:** @docs/prd-meeting-file-upload-and-display.md
**Дата:** 2026-09-11

## Фазы реализации

### Фаза 1: Backend — модель и загрузка/список файлов

**Цель:** Владелец встречи может загрузить файл через API, файл сохраняется на диске и возвращается в списке файлов встречи.
**Затрагивает:** backend, database
**Задачи:**

- [ ] E2e-тест (`test/meeting-file.e2e-spec.ts`) для сценария фазы — загрузка файла владельцем + получение списка файлов; написан до реализации, ожидаемо красный (эндпоинтов ещё нет).
- [ ] Модель `MeetingFile` в `prisma/schema.prisma` (связь с `Meeting`, поля: имя файла, MIME-тип, размер, путь хранения, дата загрузки, владелец-загрузивший), миграция применена.
- [ ] Переменные окружения: директория хранения файлов (вне `apps/api/dist`) и лимит максимального размера файла (`apps/api/.env.example`).
- [ ] `POST /meetings/:id/files` (multipart/form-data) — только владелец встречи, интерцептор/пайп с лимитом размера, сохранение на файловую систему + запись в БД.
- [ ] `GET /meetings/:id/files` — список файлов встречи (имя, размер, дата), доступен владельцу и участникам; unit-тесты на загрузку, отклонение файла сверх лимита (без сохранения на диск), запрет загрузки не-владельцем, список файлов.

**Когда готова:** e2e-тест фазы, написанный в начале как красный, стал зелёным; через API (curl/Postman) владелец загружает файл и видит его в списке с именем/размером/датой; файл сверх лимита отклоняется с ошибкой и не сохраняется на диске; unit-тесты зелёные.

### Фаза 2: Backend — скачивание и удаление файлов

**Цель:** Завершён жизненный цикл файла на бэкенде: скачивание с проверкой доступа участников и удаление владельцем.
**Затрагивает:** backend
**Задачи:**

- [x] Дополнить `test/meeting-file.e2e-spec.ts` сценарием фазы — скачивание (побайтовое совпадение) и удаление файла, включая попытки без прав доступа; написано до реализации, ожидаемо красный.
- [x] `GET /meetings/:id/files/:fileId/download` — отдаёт файл побайтово; доступ владельцу и участникам встречи (уточнить модель доступа участников на основе текущего поля `participants` у `Meeting`).
- [x] `DELETE /meetings/:id/files/:fileId` — только владелец встречи; удаляет запись в БД и файл с файловой системы.
- [x] Ошибка доступа (403/404) при попытке скачать/удалить файл пользователем без прав.
- [x] Unit-тесты: скачивание владельцем/участником/чужим пользователем, удаление владельцем/не-владельцем, ошибка «файл не найден».

**Когда готова:** e2e-тест фазы (загрузка → список → скачивание → удаление, включая проверку прав), написанный в начале как красный, полностью зелёный; скачанный файл побайтово совпадает с загруженным; владелец удаляет файл, он пропадает из списка и с диска; пользователь без прав получает ошибку доступа при скачивании/удалении; unit-тесты зелёные.

### Фаза 3: Frontend — страница встречи со списком файлов

**Цель:** Появляется страница `/meetings/[id]`, показывающая данные встречи и список уже загруженных файлов (без загрузки/удаления).
**Затрагивает:** frontend
**Задачи:**

- [x] Сценарий Playwright MCP для фазы (открыть `/meetings/[id]` владельцем и участником, проверить список файлов и скачивание) зафиксирован до реализации страницы; ожидаемо красный — страницы ещё нет.
- [x] Страница `apps/web/app/pages/meetings/[id].vue` с блоком «Файлы встречи».
- [x] Composable для работы с файлами встречи (получение списка) — по аналогии с `useMeetings.ts`.
- [x] Список файлов: имя, размер, дата загрузки, кнопка «скачать».
- [x] Владелец видит элементы загрузки/удаления, участник без прав владельца — не видит (или недоступны); обработка ошибки сети при загрузке списка файлов.

**Когда готова:** сценарий Playwright MCP фазы, зафиксированный в начале как красный, проходит зелёным; владелец и участник открывают страницу встречи и видят список прикреплённых файлов с именем/размером/датой, скачивание из UI работает; у не-владельца отсутствуют элементы загрузки/удаления; проверено визуально через Playwright MCP + skill `ui-ux-pro-max`.

### Фаза 4: Frontend — загрузка с прогрессом и удаление

**Цель:** Владелец встречи может загрузить файл через drag-and-drop или диалог с индикатором прогресса и удалить ранее загруженный файл — без перезагрузки страницы.
**Затрагивает:** frontend
**Задачи:**

- [ ] Сценарий Playwright MCP для фазы (загрузка файла с прогрессом, загрузка файла сверх лимита, удаление файла) зафиксирован до реализации; ожидаемо красный — загрузки/удаления в UI ещё нет.
- [ ] Drag-and-drop / выбор файла через диалог в блоке «Файлы встречи».
- [ ] Загрузка файла с индикатором прогресса (composable дополняется методом загрузки с отслеживанием прогресса).
- [ ] Отображение ошибок загрузки: файл не выбран, превышен лимит размера, сетевой сбой — понятные сообщения.
- [ ] Удаление файла владельцем с обновлением списка без перезагрузки страницы.

**Когда готова:** сценарий Playwright MCP фазы, зафиксированный в начале как красный, проходит зелёным (со скриншотами загрузки/ошибки/удаления); владелец загружает файл, видит прогресс, файл появляется в списке без перезагрузки страницы; превышение лимита размера показывает понятную ошибку и файл не загружается; удаление убирает файл из списка и с сервера; проверено через skill `ui-ux-pro-max`.
