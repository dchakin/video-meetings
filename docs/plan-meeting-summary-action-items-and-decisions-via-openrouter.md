# Plan: Выжимка встречи (summary, action items, решения) через OpenRouter

**PRD:** docs/prd-meeting-summary-action-items-and-decisions-via-openrouter.md
**Дата:** 2026-09-30

## Фазы реализации

### Фаза 1: Backend — схема данных и генерация выжимки (Tracer Bullet)

**Цель:** По запросу пользователя выжимка встречи генерируется через OpenRouter по всем готовым транскрипциям и сохраняется в БД со статусом. Минимальный сквозной путь без фронтенда.
**Затрагивает:** backend, database
**Задачи:**

- [x] Prisma-миграция: сущность выжимки встречи (одна на `Meeting`): статус (enum: в процессе / готово / ошибка), summary, список action items (описание + ответственный nullable), список принятых решений
- [x] Сервис генерации выжимки в новом модуле `meeting-summary`: собрать тексты транскрипций файлов встречи со статусом `DONE` (остальные статусы игнорируются), сформировать промпт (summary, action items с ответственным «как назван во встрече», решения; язык ответа — язык транскрипции; строго структурированный ответ) и отправить через существующий `OpenRouterService`
- [x] Разбор и валидация ответа модели: при корректной структуре — сохранение выжимки и статус «готово»; повторная генерация целиком заменяет предыдущую выжимку
- [x] Эндпоинт ручного запуска `POST /meetings/:id/summary`: переводит выжимку в статус «в процессе» и запускает генерацию асинхронно, не блокируя ответ; автоматического запуска после транскрибации нет
- [x] Unit-тесты сервиса (OpenRouter замокан): в промпт попадают только `DONE`-транскрипции, корректный ответ сохраняется со статусом «готово», перегенерация заменяет прежние action items и решения

**Когда готова:** Вызов `POST /meetings/:id/summary` для встречи с готовой транскрипцией приводит к записи в БД со статусом «готово», summary, action items и решениями; unit-тесты зелёные.

### Фаза 2: Backend — чтение выжимки, доступ, ошибки и защита от повторного запуска

**Цель:** Выжимка и её статус доступны через API только участникам встречи; ошибки OpenRouter и некорректные ответы модели не оставляют битых данных; параллельный запуск невозможен.
**Затрагивает:** backend
**Задачи:**

- [x] Эндпоинт `GET /meetings/:id/summary`: статус и сохранённая выжимка (без повторной генерации); проверка доступа через `isMeetingMember` для GET и POST (чужая встреча — 403/404)
- [x] Отклонение запуска в `POST`: нет ни одной транскрипции в статусе `DONE` — ошибка 4xx; генерация для встречи уже в статусе «в процессе» — 409
- [x] Обработка сбоев: ошибка/таймаут OpenRouter и ответ, не прошедший валидацию структуры, переводят статус в «ошибка» без сохранения частичных данных; после ошибки повторный запуск разрешён
- [x] Unit-тесты: невалидный ответ модели и исключение OpenRouter → статус «ошибка», данные не записаны; отказ при отсутствии `DONE`-транскрипций и при статусе «в процессе»
- [x] E2e-тест (`apps/api/test/meeting-summary.e2e-spec.ts`, OpenRouter замокан): запуск → «в процессе» → GET возвращает «готово» с тремя разделами; повторный POST во время генерации → 409; встреча без готовых транскрипций → 4xx; пользователь без доступа → 403/404 на GET и POST

**Когда готова:** E2e и unit-тесты подтверждают все серверные критерии готовности PRD: чтение без перегенерации, статусы, отказ повторного запуска, отсутствие битых данных при ошибке, контроль доступа.

### Фаза 3: Frontend — блок выжимки на странице встречи

**Цель:** Пользователь запускает генерацию/перегенерацию из встречи, видит статус с автообновлением и готовую выжимку из трёх разделов.
**Затрагивает:** frontend
**Задачи:**

- [x] Composable `useMeetingSummary`: загрузка выжимки, запуск генерации, polling статуса, пока он «в процессе» (по аналогии с `useMeetingFiles`)
- [x] Компонент `MeetingSummary.vue` (отдельный компонент — `[id].vue` уже ~230 строк): кнопка «Сгенерировать выжимку», если выжимки нет; «Перегенерировать выжимку» при статусе «готово» или «ошибка»; кнопка недоступна без готовых транскрипций и во время генерации
- [x] Отображение статуса («в процессе» / «ошибка») и трёх разделов при «готово»: summary; action items с описанием и ответственным (если назван); принятые решения; пустые разделы с пометкой «нет»
- [x] Подключить `MeetingSummary.vue` на странице `pages/meetings/[id].vue`
- [x] Ручная проверка в браузере: генерация по русской и по английской записи (язык выжимки совпадает с языком встречи), автообновление статуса без перезагрузки, выжимка сохраняется после перезагрузки страницы, перегенерация заменяет выжимку, состояние «ошибка» и кнопка перегенерации, кнопка недоступна без готовых транскрипций

**Когда готова:** В браузере пользователь запускает генерацию, видит смену статуса без перезагрузки, получает выжимку из трёх разделов на языке встречи и может её перегенерировать; все критерии готовности PRD выполнены.
