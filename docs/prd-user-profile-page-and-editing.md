# PRD: User Profile Page and Editing

**Дата**: 2026-09-15
**Статус**: Draft

## Цель

Дать пользователю возможность посмотреть свой профиль и отредактировать его: сменить отображаемое имя, загрузить аватар и сменить пароль. Аватар и имя должны быть узнаваемы на главной странице, чтобы было понятно, кто сейчас залогинен.

## Пользовательские сценарии

- Пользователь открывает страницу профиля -> видит текущее имя, email, аватар (или заглушку, если не загружен).
- Пользователь открывает страницу редактирования профиля -> меняет имя -> сохраняет -> новое имя отображается в профиле и в навбаре главной страницы.
- Пользователь загружает новое изображение аватара -> изображение сохраняется -> новый аватар отображается в профиле и в навбаре главной страницы.
- Пользователь заменяет существующий аватар новым -> старый файл аватара удаляется/перестаёт использоваться, отображается только новый.
- Пользователь вводит старый пароль, новый пароль и подтверждение нового пароля -> при совпадении и валидности данных пароль меняется, пользователь получает подтверждение.
- Пользователь вводит неверный старый пароль при смене пароля -> получает ошибку, пароль не меняется.
- Пользователь вводит новый пароль и подтверждение, которые не совпадают -> получает ошибку валидации, пароль не меняется.
- Пользователь загружает файл аватара неподдерживаемого формата или превышающий лимит размера -> получает ошибку, аватар не сохраняется.
- Новый пользователь без заданного имени открывает профиль -> в качестве имени отображается локальная часть email (до `@`).

## В скоупе

- Страница профиля (просмотр): имя, email (только чтение), аватар.
- Страница редактирования профиля: изменение имени, загрузка/замена аватара, форма смены пароля.
- Поле `name` (опциональное) и `avatarUrl` в модели `User`; дефолт имени — локальная часть email до `@`, если `name` не задано.
- Загрузка аватара: форматы JPEG/PNG/WebP, лимит размера — 5 МБ.
- Замена аватара: новая загрузка вытесняет предыдущий файл.
- Смена пароля: поля "старый пароль", "новый пароль" (мин. 8 символов), "подтверждение нового пароля"; проверка старого пароля перед сохранением.
- Отображение имени и аватара залогиненного пользователя в шапке/навбаре главной страницы (или заглушка/инициалы, если аватар не загружен).
- Валидация и понятные сообщения об ошибках для всех операций редактирования (неверный старый пароль, несовпадение паролей, неподдерживаемый формат/размер файла).

## Не в скоупе

- Изменение email пользователя.
- Удаление аккаунта.
- Восстановление/сброс пароля через email ("забыли пароль").
- Публичные профили других пользователей / просмотр чужого профиля.
- Обрезка/редактирование изображения аватара (кроп, фильтры) на клиенте.
- История смены паролей, уведомления по email о смене пароля.
- Двухфакторная аутентификация и прочие настройки безопасности, кроме смены пароля.

## Технические ограничения

- В текущей схеме `User` (Prisma) нет полей `name` и `avatarUrl` — требуется миграция БД.
- Хранение файлов аватаров ведётся аналогично существующему модулю `meeting-file` (файловое хранилище + `storagePath`/URL в БД).
- Смена пароля требует хеширования нового пароля тем же механизмом, что используется при регистрации (см. `apps/api` auth-модуль).
- Максимальный размер файла аватара — 5 МБ; на бэкенде и фронтенде должна быть согласованная валидация формата и размера.

## Критерии готовности

- [ ] Страница профиля отображает текущее имя (или дефолт из email), email и аватар (или заглушку).
- [ ] Страница редактирования позволяет изменить имя, сохранить изменения, и новое имя отражается в профиле и в навбаре главной страницы.
- [ ] Загрузка аватара в форматах JPEG/PNG/WebP до 5 МБ проходит успешно, новый аватар отображается в профиле и в навбаре главной страницы.
- [ ] Загрузка нового аватара заменяет предыдущий (старый файл больше не используется/отображается).
- [ ] Попытка загрузить файл неподдерживаемого формата или размером более 5 МБ отклоняется с понятным сообщением об ошибке.
- [ ] Смена пароля с корректным старым паролем, новым паролем (мин. 8 символов) и совпадающим подтверждением проходит успешно.
- [ ] Смена пароля с неверным старым паролем отклоняется с ошибкой, пароль не изменяется.
- [ ] Смена пароля с несовпадающими новым паролем и подтверждением отклоняется с ошибкой валидации до отправки на сервер.
- [ ] Пользователь без заданного имени видит в профиле и навбаре локальную часть своего email (до `@`) как имя по умолчанию.
