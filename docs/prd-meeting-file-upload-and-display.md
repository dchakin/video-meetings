# PRD: Загрузка файла встречи для хранения и отображения

**Дата**: 2026-09-11
**Статус**: Draft

## Цель

Дать пользователю возможность прикрепить файл (запись встречи, документ, презентацию) к конкретной встрече, сохранить его на сервере и увидеть его внутри страницы встречи — чтобы материалы встречи не терялись и были доступны в одном месте вместе с остальной информацией о встрече.

## Пользовательские сценарии

- Пользователь открывает страницу встречи, которой владеет -> видит блок загрузки файла и список уже прикреплённых файлов.
- Пользователь выбирает файл на своём устройстве и загружает его -> файл появляется в списке файлов встречи со статусом «загружен», без перезагрузки страницы.
- Пользователь видит прогресс загрузки файла -> понимает, что загрузка идёт, и не запускает её повторно.
- Пользователь пытается загрузить файл, превышающий лимит размера, -> видит понятную ошибку и файл не загружается.
- Пользователь открывает список файлов встречи -> видит имя файла, тип/расширение, размер и дату загрузки.
- Пользователь скачивает ранее загруженный файл встречи -> получает исходный файл без потери данных.
- Пользователь удаляет ранее загруженный им файл встречи -> файл пропадает из списка и удаляется с сервера.
- Пользователь, не являющийся владельцем встречи, открывает страницу встречи -> не видит форму загрузки/кнопку удаления (или видит их недоступными), но может видеть и скачивать уже прикреплённые файлы, если у него есть доступ к встрече.

## В скоупе

- Модель `MeetingFile` в Prisma: связь с `Meeting` (много файлов на одну встречу), поля — имя файла, MIME-тип/расширение, размер, путь хранения, дата загрузки, владелец (кто загрузил).
- API-эндпоинты (Nest.js, REST, в модуле `meeting` или отдельном `meeting-file`):
  - загрузка файла для встречи (multipart/form-data),
  - получение списка файлов встречи,
  - скачивание файла встречи,
  - удаление файла встречи.
- Хранение загруженных файлов на локальной файловой системе сервера (отдельная директория вне `apps/api/dist`, путь настраивается через переменную окружения).
- Ограничение максимального размера загружаемого файла (конкретное число задаётся на этапе реализации, конфигурируется через переменную окружения).
- Проверка прав: загружать и удалять файлы может только владелец встречи; просматривать и скачивать — владелец и участники встречи.
- Страница конкретной встречи на фронтенде (`apps/web`, сейчас отсутствует) с блоком «Файлы встречи»:
  - drag-and-drop или выбор файла через диалог,
  - индикатор прогресса загрузки,
  - список файлов с именем, размером, датой, действиями «скачать» / «удалить»,
  - отображение ошибок загрузки (превышен размер, недопустимый файл, сетевая ошибка).
- Composable для работы с файлами встречи на фронтенде (аналогично `useMeetings.ts`).
- Обработка базовых ошибок: файл не выбран, сетевой сбой, превышение лимита размера, файл не найден при скачивании/удалении.

## Не в скоупе

- Любая обработка содержимого файла: транскрипция, распознавание речи, AI-анализ, генерация конспекта — задел на будущую итерацию, в этой фиче файл только хранится «как есть».
- Просмотр содержимого файла прямо в браузере (видео-плеер, предпросмотр документов) — доступно только скачивание.
- Версионирование файлов (замена файла с сохранением истории версий).
- Ограничение типов файлов по MIME/расширению — принимаются любые файлы.
- Объектное хранилище (S3/MinIO) и связанная с ним инфраструктура — в этой итерации используется локальная файловая система сервера.
- Совместное редактирование или комментирование файлов.
- Уведомления участников встречи о новых загруженных файлах.
- Квоты на суммарный объём хранилища на пользователя/встречу.

## Технические ограничения

- Загрузка файлов на локальную файловую систему сервера не переживёт горизонтальное масштабирование api (несколько инстансов без общего диска) — учитывать при выборе пути хранения (директория должна быть доступна извне `apps/api/dist`, не удаляться при пересборке).
- Директория с файлами не должна коммититься в git и должна быть исключена из docker-образа как build-artefact; путь задаётся через переменную окружения в `apps/api/.env`.
- Nest.js по умолчанию не хранит тело запроса multipart в памяти без ограничений — нужен явный лимит размера файла на уровне интерцептора/пайпа, иначе большой файл может исчерпать память процесса.
- Текущая модель `Meeting` и связанная авторизация (кто «владелец», кто «участник») не содержат ролей участников — доступ на скачивание для «участников» встречи потребует уточнения модели доступа на этапе реализации.
- Страницы конкретной встречи (`/meetings/[id]`) на фронтенде ещё не существует — её создание является частью этой фичи, а не отдельной работой.

## Критерии готовности

- [ ] В Prisma-схеме добавлена модель файла встречи со связью на `Meeting`, миграция применена.
- [ ] Владелец встречи может загрузить файл через UI страницы встречи, файл сохраняется на сервере и появляется в списке без перезагрузки страницы.
- [ ] При загрузке файла отображается индикатор прогресса.
- [ ] Загрузка файла, превышающего заданный лимит размера, отклоняется с понятным сообщением об ошибке, файл на сервере не сохраняется.
- [ ] Список файлов встречи показывает имя, размер и дату загрузки каждого файла.
- [ ] Файл встречи можно скачать, и скачанный файл побайтово совпадает с загруженным.
- [ ] Владелец встречи может удалить файл; после удаления файл пропадает из списка и удаляется с файловой системы сервера.
- [ ] Пользователь без прав на встречу не может загрузить или удалить файл (API возвращает ошибку доступа, UI не показывает элементы загрузки/удаления).
- [ ] Все новые API-эндпоинты покрыты unit-тестами (api), сценарий загрузки/скачивания/удаления файла покрыт e2e-тестом.
