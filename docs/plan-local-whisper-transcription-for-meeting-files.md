# Plan: Локальная транскрибация загруженных файлов встречи через Whisper

**PRD:** docs/prd-local-whisper-transcription-for-meeting-files.md
**Дата:** 2026-09-26

## Фазы реализации

### Фаза 1: Backend — схема данных и запуск транскрибации (Tracer Bullet)

**Цель:** После загрузки mp4/mp3 файла транскрибация автоматически запускается локальным Whisper (модель low), статус и результат сохраняются в БД. Минимальный сквозной путь без учёта фронтенда.
**Затрагивает:** backend, database
**Задачи:**

- [ ] Prisma-миграция: добавить в модель `MeetingFile` поля статуса транскрибации (в очереди / в процессе / готово / ошибка) и текста транскрипции (nullable)
- [ ] Сервис интеграции с локальным Whisper (модель low), включая получение аудиодорожки из mp4 при необходимости
- [ ] Триггер запуска транскрибации в `meeting-file.service.ts` сразу после успешной загрузки файла с mimetype mp4/mp3, без блокировки ответа на запрос загрузки
- [ ] Обновление статуса файла в БД по мере прохождения этапов (в очереди → в процессе → готово/ошибка) и сохранение текста при успехе
- [ ] Юнит-тесты: сервис Whisper-интеграции (с мокированием вызова распознавания) и переходы статусов в `meeting-file.service`

**Когда готова:** После загрузки mp4/mp3 файла через API статус файла в БД автоматически проходит путь от "в очереди" до "готово" с сохранённым текстом транскрипции; юнит-тесты зелёные.

### Фаза 2: Backend — отдача статуса и текста через API, ограничение по форматам

**Цель:** Статус и текст транскрибации доступны через API, транскрибация не запускается для файлов, отличных от mp4/mp3, ошибки обработки не приводят к падению запросов.
**Затрагивает:** backend
**Задачи:**

- [ ] Добавить статус и текст транскрибации в `MeetingFileResponse` и в ответы `meeting-file.controller` (список файлов встречи)
- [ ] Явно исключить запуск транскрибации для файлов с mimetype, отличным от mp4/mp3 (статус/текст отсутствуют)
- [ ] Обработка сбоя Whisper (ошибка процесса/таймаут) — перевод статуса файла в "ошибка" без ошибки в ответе API
- [ ] Unit-тесты на исключение не-mp4/mp3 файлов и обработку ошибки транскрибации
- [ ] E2e-тест: загрузка mp4/mp3 → статус меняется на "готово" с текстом; загрузка файла другого формата → статус отсутствует

**Когда готова:** E2e и unit-тесты подтверждают все критерии готовности из PRD на уровне API: корректные статусы, отсутствие транскрибации для чужих форматов, устойчивость к ошибкам.

### Фаза 3: Frontend — отображение статуса и текста транскрипции

**Цель:** Пользователь видит статус транскрибации файла в интерфейсе встречи, обновляющийся без ручного обновления страницы, и текст готовой транскрипции.
**Затрагивает:** frontend
**Задачи:**

- [ ] Расширить `useMeetingFiles` данными статуса и текста транскрибации, добавить периодический опрос (polling) для файлов с незавершённым статусом
- [ ] Отобразить статус транскрибации (в очереди / в процессе / готово / ошибка) рядом с файлом в `MeetingFileList.vue`
- [ ] Добавить отображение текста транскрипции для файлов со статусом "готово"
- [ ] Отобразить сообщение об ошибке для статуса "ошибка" без показа текста
- [ ] Ручная проверка в браузере (golden path: загрузка mp4/mp3 и появление статуса/текста; edge case: не-mp4/mp3 файл, ошибка транскрибации)

**Когда готова:** В браузере статус транскрибации у файла обновляется автоматически по мере обработки, текст готовой транскрипции отображается, для файлов других форматов статус не показывается.
