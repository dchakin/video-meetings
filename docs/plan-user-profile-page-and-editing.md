# Plan: User Profile Page and Editing

**PRD:** docs/prd-user-profile-page-and-editing.md
**Дата:** 2026-09-15

## Фазы реализации

### Фаза 1: Backend — профиль, аватар, смена пароля

**Цель:** API для чтения профиля, изменения имени, загрузки/замены аватара и смены пароля с проверкой старого пароля.
**Затрагивает:** backend, database
**Задачи:**

- [ ] Миграция Prisma: добавить в модель `User` опциональные поля `name` (String?) и `avatarUrl` (String?); сгенерировать клиент.
- [ ] В модуле `users`: query получения профиля текущего пользователя (с дефолтом имени — локальная часть email до `@`, если `name` не задано) и command обновления имени.
- [ ] Command смены пароля: проверка старого пароля (тем же механизмом хеширования, что при регистрации/логине), валидация нового пароля (мин. 8 символов), обновление `passwordHash`.
- [ ] Загрузка аватара (по аналогии с модулем `meeting-file`): endpoint загрузки файла с валидацией формата (JPEG/PNG/WebP) и размера (до 5 МБ), сохранение в файловое хранилище, обновление `avatarUrl`, удаление предыдущего файла аватара при замене.
- [ ] Контроллер профиля (`ProfileController`) под JWT-guard: `GET /profile`, `PATCH /profile` (имя), `POST /profile/avatar`, `PATCH /profile/password`; unit-тесты на все сценарии: успешное обновление имени, успешная/неуспешная смена пароля (неверный старый пароль, короткий новый), успешная загрузка аватара и замена старого, отклонение файла неверного формата/размера, дефолтное имя из email.

**Когда готова:** Через API можно получить профиль, изменить имя, загрузить/заменить аватар и сменить пароль (с проверкой старого); все unit-тесты проходят.

### Фаза 2: Frontend — страницы профиля и отображение в шапке

**Цель:** Пользователь может посмотреть и отредактировать профиль через UI, а его имя и аватар видны в шапке главной страницы.
**Затрагивает:** frontend
**Задачи:**

- [ ] Composable для работы с профилем текущего пользователя (получение профиля, обновление состояния после изменения имени/аватара/пароля).
- [ ] Страница профиля (просмотр): имя (или дефолт из email), email (только чтение), аватар или заглушка.
- [ ] Страница редактирования профиля: форма изменения имени; загрузка/замена аватара с клиентской валидацией формата и размера (до 5 МБ) и превью; форма смены пароля (старый пароль, новый пароль, подтверждение) с клиентской валидацией (мин. 8 символов, совпадение подтверждения) и отображением серверных ошибок (неверный старый пароль).
- [ ] Шапка главной страницы: отображение аватара (или заглушки/инициалов) и имени залогиненного пользователя со ссылкой на страницу профиля.
- [ ] Ручная проверка всех пользовательских сценариев и критериев готовности из PRD (автотесты web в проекте пока не настроены, см. корневой `CLAUDE.md`).

**Когда готова:** Все пользовательские сценарии и критерии готовности из PRD воспроизводимы в браузере: просмотр профиля, изменение имени, загрузка/замена аватара, смена пароля (успех и ошибки), отображение имени и аватара в шапке главной страницы.
