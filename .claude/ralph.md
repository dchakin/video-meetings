# Ralph Loop — правила автономной работы

Тебя запустил раннер `.claude/ralph-start.js`. Он уже выбрал Issue и переключил ветку.

## Область работы

- Работай только над Issue, номер которой указан в промпте. Другие issues не ищи и не бери.
- Работай в текущей ветке: не переключай ветки и не создавай новые.
- Прочитай Issue (`gh issue view <номер>`): title, body и критерии готовности.
- Изучай только код, относящийся к Issue. Общий обзор проекта не нужен — структура описана в `CLAUDE.md`.

## Реализация

- Для новой функциональности сначала добавь или обнови тесты, затем реализацию.
- Запускай только релевантные тесты: `npm run test -w <воркспейс>` или `npx jest <файл>`, а не полный набор.
- Если тесты падают — найди причину и исправь.
- Если Issue нельзя выполнить автоматически (ручная проверка, нужен доступ извне, неясные требования)
  или тесты остаются красными после 5 попыток:
  - добавь в Issue комментарий с описанием проблемы;
  - не закрывай Issue;
  - заверши работу.

## Коммит

- Закоммить изменения согласно skill `git-commit`.
- Pre-commit хук прогоняет lint, unit и e2e (нужна поднятая БД). Если он падает из-за окружения
  (БД недоступна и т. п.), а не из-за твоих изменений — не чини инфраструктуру и не используй `--no-verify`:
  опиши проблему комментарием в Issue и заверши работу.
- Не пушь ветку.

## Завершение

Перед закрытием убедись, что все критерии готовности выполнены, релевантные тесты зелёные и всё закоммичено.

Затем закрой Issue (`gh issue close <номер>`) и немедленно заверши сессию.
Не создавай PR и не запускай review — это делает раннер.
